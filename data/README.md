# Data notes

Everything in this folder (except `raw/`, which is gitignored) is derived from public
Australian government data. `occupations.csv` is the merged table; `scores.json` is the
LLM-scored AI exposure layer; `parse-report.md` is auto-generated by `parse.py` and has
the exact row counts and coverage per layer for the run that produced this copy of the
data. This file is the human-written version: what each source is, when it was
published, its licence, and the gaps that are real and worth knowing about before you
trust a number on the map.

## Sources

All five sources are Creative Commons Attribution 4.0 International (CC BY 4.0). Exact
URLs, release dates, and the date each was verified reachable are in `../sources.yaml`.

| Source | Publisher | What it gives the map |
|---|---|---|
| Labour Force, Australia, Detailed - table EQ08 | ABS | Employment (headcount) per occupation |
| Employee Earnings and Hours, Australia - Data Cube 11 | ABS | Average weekly earnings per occupation |
| ANZSCO 2022 classification structure | ABS | The master list of occupation codes, titles, and major groups |
| Employment Projections | Jobs and Skills Australia | 5-year and 10-year projected employment growth |
| Occupation Shortage List - Unit Group Shortage List | Jobs and Skills Australia | National skills shortage rating |

Attribution: "Contains data that is (c) Commonwealth of Australia (Australian Bureau of
Statistics; Jobs and Skills Australia) 2026, used under CC BY 4.0."

## Known gaps, honestly

- **Earnings is a mean, not a median.** The brief for this project wanted median
  earnings. ABS Employee Earnings and Hours only publishes an average (mean) weekly
  total cash earnings at ANZSCO unit group level, not a median. The CSV column is named
  `avg_weekly_earnings`, not `median_weekly_earnings`, precisely so nobody downstream
  mistakes one for the other.
- **Task descriptions are not available in bulk.** Neither ABS nor JSA publish a
  downloadable file of task lists or lead statements per occupation. ABS has them, but
  only as one HTML page per unit group (roughly 360 pages) under "Browse Classification"
  - not worth scraping for this build. `tasks_text` ships empty for every occupation.
  `score.py` asks the model to infer likely typical tasks from the title and major group
  before scoring, and this is disclosed as a weaker input in `prompts/ai-exposure.md`
  and on the site's "about" panel, not hidden.
- **Coverage is not 100% on every layer.** See `parse-report.md` for the exact numbers
  from the last parse run. Earnings has real ABS suppression (occupations too small to
  survey reliably). Growth and shortage rating have some vintage mismatch between JSA's
  occupation list and the ABS 2022 ANZSCO structure used as the master list. The site
  shows "no data" for a missing cell rather than plotting a zero.
- **Employment is derived, not published as a total.** EQ08's underlying data cube has
  no pre-aggregated "Australia, Persons" row - it only has Male and Female counts for
  each of the 8 states and territories. `parse.py` sums those for the most recent
  quarter. See the comment on `load_employment()` in `../parse.py` for the exact logic.
- **AI exposure scores are LLM output, not a survey.** They come from a rubric prompt
  scored by a single model in one pass, mostly from occupation titles rather than full
  task lists (see above). Treat them as a starting point for a conversation, not a
  finding. Full methodology: `../prompts/ai-exposure.md`.

## Regenerating this data

```
uv run python fetch.py
uv run python parse.py
uv run python score.py --backend claude-cli
uv run python build_site.py
```

`fetch.py` skips files already on disk, so reruns are cheap. If a government department
renames or moves a release (the ABS Labour Force product was flagged as being retired
around when this was built), update the URL in `../sources.yaml`, not in the scripts.
